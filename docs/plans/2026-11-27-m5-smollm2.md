# M5 SmolLM2-135M Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** load the real SmolLM2-135M weights from Hugging Face's `safetensors` and `config.json`, and reproduce its reference logits and greedy generations, on the CPU and on CUDA. `titan generate --hf-model <dir>` runs it from the CLI.

**Architecture:**

- **`io::SafetensorsFile`.** A generic, bounds-checked reader of the safetensors container. It parses the header and reads one tensor at a time as FP32, converting BF16 and F16 exactly.
- **`runtime/hf_model.*`.** It parses a Hugging Face Llama `config.json` into a `ModelConfig` through an allowlist. It maps Hugging Face tensor names onto our parameter names and loads `config.json`, `model.safetensors` and `tokenizer.json` from a directory into a ready `Model` and tokenizer. The architecture (GQA, SwiGLU, RMSNorm, half-split RoPE, tied embeddings) already exists, so no `nn` or `ops` change is expected.
- **Golden fixtures.** `tools/make_llama_fixtures.py` runs Hugging Face `transformers` in FP32 on the CPU and writes the reference outputs.
  - Two tiny random Llama models (tied and untied) are committed with their weights, so CI checks the whole path.
  - SmolLM2-135M's reference outputs are committed. Its weights stay in the git-ignored `models/`, and the tests that need them skip when they are absent.

**Tech Stack:** C++20, CMake presets, MSVC 14.38, CUDA 12.6, the project's own test harness. Development only: `tools/.venv` with `torch` 2.15.0 (CPU build), `transformers` 5.23.0, `safetensors` 0.8.0 and `tokenizers` 0.23.3, from `tools/requirements-fixtures.txt` (ADRs 0004 and 0009; installed). No new library dependencies.

**Spec:** `docs/specs/2026-11-19-neuraltitan-design.md`: §1 (final correctness target), §5.3 (weight loaders), §5.7 (`titan generate --hf-model`), §6 (golden reference), §7 M5, and §9 (RoPE layout; the SmolLM2 match criteria). Also `docs/architecture/overview.md` §9 (T1, T5) and §10 (layer rules), and ADR 0004.

## Global Constraints

- **Pass conditions (spec §9).** The golden fixtures are produced by Hugging Face in FP32, with the BF16 weights upcast exactly as our loader does.
  - The logits for each fixture prompt match within `max |Δ| ≤ 1e-3` relative to the logit scale. This plan reads that as `max |Δ| ≤ 1e-3 · max(1, max |reference logit|)` over every compared value of the prompt (decision 4).
  - Greedy generation matches the first 32 tokens.
  - A divergence is accepted only at a near-tie, where the reference's top-2 logit gap at that step is below the same tolerance. Comparison of that prompt stops there.
  - Bit-exact agreement between the CPU and CUDA is not required. Both devices must meet the tolerance.
- **Libraries.** No library beyond the C++ standard library, the CUDA runtime and cuBLAS.
- **Input validation.** Validate external input only at the `io` boundary, in the `runtime` config parser built on `io::JsonFields`, and in `cli`.
  - `model.safetensors` and `config.json` are external input (threat T1). Bounds-check every length, offset and shape before allocating or reading. Reject what this plan does not support with an error naming the file, the field or tensor, and the value.
  - Every parser gets malformed-input tests.
- **Errors.** Throw `titan::Error` with context: the file, the tensor or field name, the shapes.
- **Layers.** `io` depends only on `core`. `runtime/hf_model` may use `io`, `model` and `tokenizer`. The layer check stays green.
- **Golden fixtures.** These come from `tools/make_llama_fixtures.py`. Regenerate them; never edit them. SmolLM2 is pinned at revision `93efa2f097d58c2a74874c7e644dbc9b0cee75a2` (Apache-2.0, notice in `tests/fixtures/smollm2/NOTICE.md`). The weights are never committed.
- **Math notes.** `docs/math/hf-llama.md` covers:
  - the BF16 and F16 to FP32 conversion;
  - the mapping of a Hugging Face Llama onto our blocks;
  - the RoPE layout and theta;
  - the tolerance and why it is relative.

  Docs are additive.
- **Change rules.**
  - Edit `CMakeLists.txt` files through the shell, not the Edit/Write tools.
  - Conventional Commits, with no AI attribution, in English.
  - Work on branch `feat/m5-smollm2`, from `main`.
  - `scripts/check.ps1` prints `check: OK` after every task.
  - Prove each new test catches a deliberate break before committing.

## Review Focus

1. **A crafted or truncated safetensors file.** Offsets past the end of the file, overlapping or out-of-order ranges, a shape whose product overflows or disagrees with the byte range, a header length larger than the file, an unknown dtype, or a duplicate name. Each fails with a named error before any large allocation. Pinned in Task 1 (`Safetensors.Rejects*`).
2. **A `config.json` for a model we compute differently.** Examples: `rope_scaling` set, `attention_bias` true, `hidden_act` "gelu", a `head_dim` other than `hidden_size / num_attention_heads`, `rope_interleaved` true, or an unknown key. Each is rejected with the field named, never loaded silently. Pinned in Task 2 (`HfConfig.Rejects*`).
3. **A weights file that doesn't match its config.** A missing tensor, an extra tensor, a wrong shape, or `lm_head.weight` present while `tie_word_embeddings` is true. Each fails before the model is used. Pinned in Task 2 (`HfModel.Rejects*`).
4. **Prompts longer than one token, and generation past many steps.** RoPE positions and the KV cache stay right across the prompt and 32 generated tokens, on both devices. Pinned in Task 4 by per-position logits and 32-step greedy runs.
5. **BF16 edge values.** Zero, negative zero, subnormals, infinities and NaN convert exactly. F16 likewise. Pinned in Task 1 (`Safetensors.ConvertsBf16`, `Safetensors.ConvertsF16`).

## Decisions (approved by the author)

1. **Branch.** `feat/m5-smollm2` starts from `main` (PR #5 merged).
2. **Weights and CI.** Two tiny random Llama models are generated by `transformers` with a fixed seed, stored in BF16, and committed with their full reference logits, so CI tests the loader and the numerics. The real SmolLM2-135M is downloaded by the tools script into the git-ignored `models/SmolLM2-135M/`, and its tests skip when its weights are absent.
3. **Fixture format.** For SmolLM2, 4 prompts. For each one:
   - the full logits at the last prompt position;
   - the logits of 1,024 seeded vocabulary ids at every prompt position;
   - the reference greedy tokens (32, or fewer if `<|endoftext|>` comes first) and the top-2 gap at each generated step.

   Tensors go in `golden.safetensors`, written by Python and read by our own reader. Prompts, ids and the sampled vocabulary ids go in `golden.json`.
4. **Tolerance.** `max |Δ| ≤ 1e-3 · max(1, max |reference logit|)` per prompt, on the CPU and on CUDA.
5. **Loader location.** `io::SafetensorsFile`, plus `runtime/hf_model.*` for the config parser, the name map and the directory loader.
6. **`config.json` strictness.** An allowlist: every key is either used or listed as irrelevant, and any other key is rejected. Unsupported values are rejected with the field name.
7. **CLI.** `titan generate --hf-model <dir>`, mutually exclusive with `--checkpoint`.
   - It takes the same sampling flags, and `--seed` defaults to 0.
   - It stops at the tokenizer's end-of-text token.
   - The context length is `max_position_embeddings`, with the existing window slide beyond it.
8. **Python tooling.** The CPU build of `torch` 2.15.0 and `safetensors` 0.8.0 in `tools/.venv`, pinned in `tools/requirements-fixtures.txt` (done in b3a8b88). CI installs only `tools/requirements-dev.txt`.
9. **Demo.** A README "M5 result" section, covering:
   - the worst logit error on the CPU and on CUDA;
   - the greedy match for each prompt;
   - SmolLM2 tokens/s on the CPU and on CUDA;
   - one sample generation.

  ```json
   "hidden_act": "silu", "hidden_size": 576, "initializer_range": 0.041666666666666664,
   "intermediate_size": 1536, "is_llama_config": true, "max_position_embeddings": 8192,
   "model_type": "llama", "num_attention_heads": 9, "num_hidden_layers": 30,
   "num_key_value_heads": 3, "pretraining_tp": 1, "rms_norm_eps": 1e-05,
   "rope_interleaved": false, "rope_scaling": null, "rope_theta": 100000,
   "tie_word_embeddings": true, "torch_dtype": "bfloat16",
   "transformers_version": "4.40.1", "use_cache": true, "vocab_size": 49152}
  ```

  `generation_config.json` holds `bos_token_id` 0 and `eos_token_id` 0.
- **`model.safetensors`:**
  - 269,060,552 bytes, with a header of 30,528 bytes. `__metadata__` is `{"format": "pt"}`.
  - 272 tensors, all BF16. There is no `lm_head.weight` (the embeddings are tied).
  - `model.embed_tokens.weight` is [49152, 576].
  - Per layer `model.layers.N.`:
    - `input_layernorm.weight` [576] and `post_attention_layernorm.weight` [576];
    - `self_attn.q_proj.weight` [576, 576], `k_proj` [192, 576], `v_proj` [192, 576] and `o_proj` [576, 576];
    - `mlp.gate_proj.weight` [1536, 576], `up_proj` [1536, 576] and `down_proj` [576, 1536].
  - `model.norm.weight` is [576].
  - The tensors are stored sorted by name, contiguously, from offset 0 to 269,030,016.
- **Name map** (Hugging Face → ours; both use the weight layout (out, in)):
  - `model.embed_tokens.weight` → `embed_tokens.weight`;
  - `model.layers.N.input_layernorm.weight` → `blocks.N.norm1.weight`;
  - `model.layers.N.post_attention_layernorm.weight` → `blocks.N.norm2.weight`;
  - `model.layers.N.self_attn.{q,k,v,o}_proj.weight` → `blocks.N.attn.{q,k,v,o}_proj.weight`;
  - `model.layers.N.mlp.{gate,up,down}_proj.weight` → `blocks.N.mlp.{gate,up,down}_proj.weight`;
  - `model.norm.weight` → `final_norm.weight`;
  - `lm_head.weight` → the untied head's weight (only when `tie_word_embeddings` is false).
- **Our `ModelConfig` for SmolLM2:**
  - `vocab_size` 49152, `dim` 576, `context_length` 8192, `rope_theta` 100000, `norm_eps` 1e-5, tied embeddings, `final_norm` "rmsnorm";
  - 30 blocks with `n_heads` 9, `n_kv_heads` 3, `mlp` "swiglu", `mlp_hidden` 1536, `norm` "rmsnorm", `position` "rope".
- **Size.** 134,515,008 parameters, about 538 MB in FP32. A full 8192-token KV cache is 30 · 2 · 8192 · 192 · 4 B ≈ 377 MB.
- **Tokenizer.** It adds no BOS, because its post-processor is null, so the prompt ids are exactly `encode(prompt)`. `<|endoftext|>` is id 0.
- **`transformers` 5.x** may write `rope_parameters: {"rope_type": "default", "rope_theta": …}` and `dtype` instead of the 4.x `rope_theta` and `torch_dtype`. The config parser accepts both forms (Task 2), because the tiny fixtures are written by 5.23.0 and SmolLM2's file by 4.40.1.

### Task 1: The safetensors reader

**Files:**

- Create: `src/io/safetensors.{hpp,cpp}`, `tests/io/safetensors_test.cpp`, `tests/support/safetensors_writer.{hpp,cpp}`, `docs/math/hf-llama.md` (the conversion section)
- Modify: `src/io/CMakeLists.txt`, `tests/CMakeLists.txt`, `docs/math/README.md`, `docs/architecture/overview.md` (the io row, and T1's mitigation)

**Interfaces:**

- Produces `io::SafetensorsDtype { F32, F16, BF16 }` and `struct io::SafetensorsEntry { std::string name; SafetensorsDtype dtype; std::vector<std::int64_t> shape; std::uint64_t begin, end; }`. Offsets are relative to the data section.
- Produces `class io::SafetensorsFile`:
  - `static SafetensorsFile open(const std::filesystem::path&)` reads and validates the header only.
  - `const std::vector<SafetensorsEntry>& entries() const` returns the entries sorted by name.
  - `const SafetensorsEntry* find(std::string_view name) const`.
  - `std::vector<float> read_f32(const SafetensorsEntry&) const` reads that byte range and converts it.
  - `const io::JsonValue& metadata() const` returns `__metadata__`, or an empty object.
- Produces `float io::bf16_to_f32(std::uint16_t)` and `float io::f16_to_f32(std::uint16_t)`.
- Test support: `void write_safetensors(const std::filesystem::path&, const std::vector<TestTensor>&, std::string_view header_override = {})`, where `TestTensor{name, dtype string, shape, raw bytes}`. The override writes a hand-written header for the malformed tests.

**Validation** (each check names the file and, where one applies, the tensor):

- The file is at least 8 bytes long. The header length `N` (u64, little-endian) satisfies `8 + N ≤ file size` and `N ≤ 100 MiB`.
- The header is a JSON object of tensor entries and an optional `__metadata__` object of strings. Duplicate keys are rejected; the existing parser already does this.
- Each entry has exactly `dtype`, `shape` and `data_offsets`.
  - `dtype` is one of F32, F16, BF16; any other dtype is rejected and named.
  - The shape entries are non-negative and their product does not overflow.
  - `end - begin == product · dtype size`.
  - `end ≤ file size − 8 − N`.
- Sorted by `begin`, the ranges are contiguous: they start at 0, each one begins where the previous one ends, and the last one ends at the end of the data section. This is what the reference `safetensors` library enforces. A gap or an overlap is rejected as "data not contiguous", naming the tensor. Trailing spaces in the header are allowed, since the format pads with them.

- [ ] **Step 1: Write the failing tests:**
  - `Safetensors.ReadsAllDtypes`: an F32, an F16 and a BF16 tensor written by `write_safetensors` read back with the right names, shapes and values.
  - `Safetensors.ConvertsBf16`: `0x0000` gives 0, `0x8000` gives −0 (check the sign bit), `0x3F80` gives 1, `0xC040` gives −3, `0x0001` gives the smallest subnormal `2^-133`, `0x7F80` gives +inf, `0xFF80` gives −inf, and `0x7FC0` gives a NaN.
  - `Safetensors.ConvertsF16`: `0x3C00` gives 1, `0xC000` gives −2, `0x0001` gives `2^-24`, `0x03FF` gives `1023 · 2^-24`, `0x7C00` gives +inf, `0x7E00` gives a NaN, and `0x8000` gives −0.
  - `Safetensors.EmptyTensor`: shape [0] with begin == end reads as an empty vector.
  - `Safetensors.Rejects*`, one test each:
    - a file shorter than 8 bytes;
    - a header length past the end of the file;
    - header JSON that is not an object;
    - a dtype "I8";
    - a missing `data_offsets`;
    - an extra entry key;
    - `end < begin`;
    - `end` past the data section;
    - a size that disagrees with the shape;
    - overlapping ranges;
    - a gap between ranges;
    - a shape with a negative dimension;
    - a shape whose product overflows int64;
    - a non-string metadata value.

    Each asserts that the message contains the tensor name or the field.
- [ ] **Step 2: Run them; verify they fail.**
- [ ] **Step 3: Implement.** Read the header with one bounded read, then read each tensor's byte range on demand, with no whole-file read. The conversions use bit operations only: BF16 is `u16 << 16`; F16 handles subnormals, infinities and NaN by its exponent field. Add the conversion section of `docs/math/hf-llama.md`.
- [ ] **Step 4: Run the tests, then `scripts/check.ps1`.** Expected: PASS, and `check: OK`.
- [ ] **Step 5: Commit** with the message `feat(io): read safetensors files`.

  - The tokenizer's `vocab_size` must equal the config's, and its `eos_id` must equal `eos_token_id`.
  - Every Hugging Face tensor maps to exactly one of our parameters, with an equal shape. Missing, extra or duplicate mapped tensors are rejected before any parameter changes, as are `lm_head.weight` with tied embeddings and a missing `lm_head.weight` with untied ones.
  - The weights are converted to FP32 into the parameters.

Prompt ids are `tokenizer.encode(prompt)` from `tokenizers` with no added special tokens. Greedy runs use `generate(do_sample=False, max_new_tokens=N, eos_token_id=0, output_scores=True, return_dict_in_generate=True)`, with `N` = 32 for SmolLM2 and 16 for the tiny models. The greedy tokens exclude the prompt and a final end-of-text token.
- **SmolLM2.** Weights in `models/SmolLM2-135M/`, downloaded at the pinned revision if they are missing (`config.json`, `generation_config.json`, `model.safetensors`, `tokenizer.json`).

  - `golden.json`:
    - `{"revision", "tolerance": 1e-3, "sample_ids": [...], "prompts": [{"text", "ids": [...], "greedy": [...], "greedy_gaps": [...]}]}`;
    - `greedy_gaps[k]` is the reference top-2 logit gap at generated step k.
  - `golden.safetensors` (F32): `p{i}.last` [vocab], `p{i}.sampled` [T, 1024] and `p{i}.top2_gap` [T], for the prompt positions.
- **Tiny models.**
  - Prompts: 3 strings, `"to be or not"`, `"the king"` and `"ROMEO:\n"`.
