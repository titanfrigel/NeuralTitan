# M0 Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A building, tested NeuralTitan skeleton. It has:
- the CMake build on MSVC 14.38 + CUDA 12.6 (`sm_86`);
- the `core` layer (errors, devices, caching CUDA allocator, `Tensor` on CPU and CUDA with explicit copies);
- the project's own test harness;
- a `titan` CLI stub;
- the layer-rule check;
- a single `check` entry point, plus the repository tooling around it.

**Architecture:** One CMake static library per layer under `src/<layer>/`; M0 creates only `titan_core`. Headers are included as `"<layer>/<file>.hpp"`, with `src/` as the include root. `core` talks to the GPU through the CUDA runtime API only, so it needs no `.cu` files yet. The project still enables the CUDA language so the toolchain is verified from day one.

**Tech Stack:** C++20, CUDA 12.6, MSVC 14.38, CMake ≥ 3.28 with the Ninja generator (the CMake 4.2 and Ninja bundled with Visual Studio 2026 are used through the developer environment), PowerShell for the `check` script.

**Spec:** `docs/specs/2026-11-19-neuraltitan-design.md`, with `docs/architecture/overview.md` (layer rules, error handling) and ADRs 0002, 0005 and 0007.

## Global Constraints

- C++20 for host and device code; `CMAKE_CUDA_ARCHITECTURES 86`; MSVC host toolset 14.38. Configuration must fail with a clear message when `MSVC_VERSION >= 1950`, because CUDA 12.6's `host_config.h` rejects it.
- Library code links only the C++ standard library, the CUDA runtime (`CUDA::cudart`) and, from M2 on, cuBLAS (`CUDA::cublas`) in `ops/cuda` only (ADR 0007). M0 links nothing to cuBLAS.
- Every external tool or CI action added in Task 8 goes through the decision gate and gets an accepted ADR before it is installed.
- Errors: exceptions derived from `titan::Error`. Use `TITAN_CHECK` for preconditions and `TITAN_CUDA_CHECK` around every CUDA runtime call. Messages carry context (shapes, byte counts, device).
- Tensors: FP32 only, row-major contiguous, rank 1 to 4, every dimension ≥ 1.
- CUDA tests call `TITAN_SKIP_IF_NO_CUDA()` and skip cleanly where no GPU exists (CI).
- All code, comments and docs are in English. Commits use Conventional Commits, with no AI attribution.
- Work happens on branch `feat/m0-skeleton`; one PR into `main`, titled `feat: m0 skeleton (build, core tensor, test harness, check)`.

## Review Focus

1. **No GPU or driver** (CI runners, a laptop on battery with the dGPU off):
   - `cuda_available()` returns false and CUDA tests report SKIP;
   - `titan info` prints `CUDA: not available`;
   - creating a CUDA tensor throws `titan::Error` instead of crashing. Pinned in Tasks 3 and 7.
2. **Invalid shapes:**
   - rank 0 or rank > 4;
   - a dimension ≤ 0;
   - `from_vector` or `reshape` with a mismatched element count.
   
   Each must throw `titan::Error` with both shapes in the message. Pinned in Task 5.
3. **GPU out of memory:**
   - a request larger than VRAM throws `titan::Error` naming the requested bytes, after one retry following `release_cached()`;
   - the allocator stays consistent and usable afterwards. Pinned in Task 4.
4. **Out-of-range views:** `slice_rows` with `begin ≥ end`, `end > dim(0)` or a negative index throws; a valid slice shares storage and sees writes. Pinned in Task 5.
5. **Running `check` from a plain shell, or with the 14.50 toolset active:**
   - the script enters the 14.38 developer environment itself;
   - a configure attempt under MSVC ≥ 1950 fails with the message naming 14.38. Pinned in Tasks 1 and 7.

### Task 4: Storage and caching CUDA allocator

**Files:**
- Create: `src/core/cuda_allocator.hpp`, `src/core/cuda_allocator.cpp`, `src/core/storage.hpp`, `src/core/storage.cpp`, `tests/core/allocator_test.cpp`, `tests/core/storage_test.cpp`
- Modify: `src/core/CMakeLists.txt`, `tests/CMakeLists.txt`

**Interfaces:**
- Consumes: `TITAN_CHECK`, `TITAN_CUDA_CHECK`, `Device`, `cuda_available()` (Task 3).
- Produces, in namespace `titan`:
  - `class CudaCachingAllocator`:
    - `static CudaCachingAllocator& instance();`
    - `void* allocate(std::size_t bytes);`
    - `void deallocate(void* ptr, std::size_t bytes);`
    - `void release_cached();`
    - `std::size_t cached_bytes() const;`
    - `std::size_t allocated_bytes() const;`
    - Sizes are rounded up to a multiple of 512 bytes. Freed blocks go to a free list keyed by exact rounded size, and `allocate` reuses an exact-size block first. If `cudaMalloc` fails with `cudaErrorMemoryAllocation`, it calls `release_cached()` and retries once. If that also fails, it throws `titan::Error` with the message `"CUDA out of memory: requested <N> bytes (allocated <A>, cached <C>)"`. Every operation is guarded by a `std::mutex`.
  - `class Storage` (non-copyable, non-movable; always held by `std::shared_ptr<Storage>`):
    - `Storage(Device device, std::size_t bytes);`
    - `~Storage();`
    - `void* data();` and `const void* data() const;`
    - `std::size_t bytes() const;`
    - `Device device() const;`
    - CPU memory comes from `::operator new(bytes, std::align_val_t{64})`. CUDA memory comes from the allocator. `bytes == 0` is rejected with `TITAN_CHECK`. Constructing CUDA storage when `!cuda_available()` throws `titan::Error` containing `"CUDA not available"`.

- [ ] **Step 1: Write the tests.** All the CUDA tests use `TITAN_SKIP_IF_NO_CUDA()`.
  - `Allocator.ReusesFreedBlock`: allocate 1000 bytes, deallocate, allocate 1000 again. Same pointer; `cached_bytes() == 0` after the reuse.
  - `Allocator.RoundsTo512`: allocating 1 byte makes `allocated_bytes()` grow by 512.
  - `Allocator.OutOfMemoryThrowsAndRecovers`: allocating `size_t{1} << 40` bytes throws `titan::Error` whose message contains `"requested 1099511627776 bytes"`. A following 1 MB allocate and deallocate still works.
  - `Storage.CpuIsAligned`: `reinterpret_cast<std::uintptr_t>(data()) % 64 == 0`.
  - `Storage.ZeroBytesRejected`: `Storage(Device::CPU, 0)` throws `titan::Error`.
  - `Storage.CudaFreesToCache`: after a CUDA `Storage` of 4096 bytes is destroyed, `cached_bytes()` has grown by 4096.
- [ ] **Step 2: Run and see it fail.** Expected: compile errors.

### Task 5: Tensor

**Files:**
- Create: `src/core/tensor.hpp`, `src/core/tensor.cpp`, `tests/core/tensor_test.cpp`

**Interfaces:**
- Consumes: `Storage`, `Device`, `TITAN_CHECK`, `TITAN_CUDA_CHECK` (Tasks 3–4).
- Produces, in namespace `titan`:
  - `using Shape = std::vector<std::int64_t>;` and `std::string to_string(const Shape&);` The string format is `"[2, 3]"`.
  - `class Tensor` (cheap to copy: it shares storage; members are `std::shared_ptr<Storage> storage_`, `std::int64_t offset_` (in elements) and `Shape shape_`):
    - **Factories:**
      - `static Tensor empty(Shape shape, Device device);` (uninitialized);
      - `static Tensor zeros(Shape shape, Device device);`
      - `static Tensor from_vector(std::span<const float> values, Shape shape, Device device = Device::CPU);`
    - **Shape queries:** `const Shape& shape() const;`, `int rank() const;`, `std::int64_t dim(int i) const;` (negative `i` counts from the end), `std::int64_t numel() const;`
    - **Data access:** `Device device() const;`, `float* data();` and `const float* data() const;` (a device pointer for CUDA, already offset).
    - **Copies:** `Tensor to(Device device) const;` copies when the device differs and returns `*this` when it matches. `Tensor clone() const;` always deep-copies on the same device. `std::vector<float> to_vector() const;` copies to the host from either device.
    - **Views (share storage):** `Tensor reshape(Shape shape) const;` and `Tensor slice_rows(std::int64_t begin, std::int64_t end) const;` (half-open range `[begin, end)` along dim 0).
    - **Mutation:** `void zero_();` (`std::memset` or `cudaMemset`).
    - **Identity:** `bool shares_storage_with(const Tensor& other) const;`
  - Shape validation, in one private `validate_shape`: rank 1 to 4, every dimension ≥ 1, and `numel` computed with an overflow check against `INT64_MAX / sizeof(float)`. The error message contains `to_string(shape)`.

### Task 6: Layer-rule check

**Interfaces:**
- Produces: `cmake -DSRC_DIR=<dir> -P scripts/check_layers.cmake`. Exit code 0 with `layer check: OK (<n> files)` on success. Otherwise a `FATAL_ERROR` listing every violation as `<file>:<line>: <layer> may not include <target>`.
- The rules are a copy of the table in `docs/architecture/overview.md` §10, held in one map in the script.
  - **Layer of a file:** the first path component under `SRC_DIR`, except that paths under `ops/cpu/` and `ops/cuda/` count as their own layers `ops/cpu` and `ops/cuda`.
  - **Target of an include:** computed the same way from the include path of each `#include "..."`.
  - **CUDA header rule:** `#include <cuda_runtime.h>`, `<cuda.h>` and `<cuda_runtime_api.h>` are allowed only in `core` and `ops/cuda`. `<cublas_v2.h>` is allowed only in `ops/cuda`.
  - **Scanned files:** `*.hpp`, `*.cpp`, `*.cu`, `*.cuh`. A file's own layer is always allowed.
