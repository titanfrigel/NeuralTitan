# M4 BPE Tokenizer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a byte-level BPE tokenizer that trains merges on a corpus and loads SmolLM2-135M's `tokenizer.json`. On fixture strings it encodes to exactly the token ids the Hugging Face reference produces. Training, checkpoints, `titan generate` and the CLI accept it next to the character tokenizer.

**Architecture:**

- **Pre-tokenizer.** `tokenizer` gains a hand-written pre-tokenizer: SmolLM2's `Digits(individual_digits)` followed by the GPT-2 `ByteLevel` split. It is backed by Unicode category tables that a `tools/` script generates and that are committed as C++ source.
- **`BpeTokenizer`.** It maps bytes to the GPT-2 byte-level alphabet and applies merges by rank. Added (special) tokens are split off before pre-tokenization. It reads and writes the Hugging Face `tokenizer.json` layout, restricted to the features SmolLM2 and our trainer use.
- **Trainer.** It counts words once, then merges the most frequent pair with incremental pair-count updates. A naive full-recount version is kept as the test oracle.
- **`Tokenizer` interface.** It lets `runtime` and the CLI use either tokenizer. `Generator` gains an optional stop token, and the CLI streams UTF-8 safely when one character spans several tokens.

**Tech Stack:** C++20, CMake presets, MSVC 14.38, the project's own test harness. Development only: Python 3.13 in `tools/.venv` with `transformers` 5.23.0 (ADR 0004; it brings `tokenizers` 0.23.3). It is used only to generate fixtures and is never part of the build. No new library dependencies.

**Spec:** `docs/specs/2026-11-19-neuraltitan-design.md`: §5.5 (tokenizer), §5.7 (`titan tokenizer train`), §6 (golden fixtures under `tools/`), §7 M4, §9 (Unicode tables generated by a `tools/` script). Also `docs/product/requirements.md` FR-9, `docs/architecture/overview.md` §9 (T1) and §10 (layer rules), and ADR 0004.

## Review Focus

1. **Text that splits a UTF-8 character across tokens.** Output stays valid when generating with a BPE tokenizer. The CLI never prints half of a multi-byte character as soon as it is sampled; it prints the character once its last byte arrives. A sequence still incomplete at the end of generation is printed as its raw bytes. Pinned in Task 5 (`Utf8.CompletePrefix*`) and Task 6 (`cli_generate_bpe_utf8`).
2. **Special tokens inside ordinary text.** `<|endoftext|>` and `<|im_start|>` in the middle of a word, adjacent specials, and a partial `<|endoftext` all encode exactly as Hugging Face does. Pinned in Task 3 by fixture strings.
3. **A malformed or unsupported `tokenizer.json`** fails with a clear error naming the field, never a crash or a silently different tokenizer. This covers:
   - a merge whose parts or result are missing from the vocabulary;
   - duplicate or out-of-range ids;
   - a missing byte symbol;
   - a normalizer or pre-tokenizer we don't implement;
   - an added token whose id disagrees with the vocabulary.

   Pinned in Task 2 (`Bpe.FromJsonRejects*`).
4. **Non-ASCII numbers and whitespace.** Arabic-Indic digits, Roman numerals, ½, the no-break space, U+3000 and U+2028 follow the same letter, number and whitespace classes as the reference. Pinned in Task 1 (`Pretokenize.*`) and Task 3 (fixtures).
5. **Training on a corpus that runs out of pairs before reaching `--vocab`.** This applies to a tiny corpus, or a corpus with one repeated word. Training stops cleanly with the smaller vocabulary and reports it. It is deterministic across runs. Pinned in Task 4 (`BpeTrain.StopsWhenNoPairRepeats`, `BpeTrain.Deterministic`).

## Decisions (approved by the author)

1. **Branch.** `feat/m4-bpe-tokenizer` is stacked on `feat/m3-inference`, then rebased onto `main` after PR #4 merges.
2. **Reference data.**
   - `transformers` 5.23.0 is installed in `tools/.venv` (done; torch waits for M5).
   - SmolLM2's `tokenizer.json` is downloaded and committed under `tests/fixtures/smollm2/` with its notice, so CI checks M4.
   - Whole-corpus equality on TinyShakespeare is checked through a token count and a CRC-32. That test skips when `data/tinyshakespeare/input.txt` is absent.
3. **Unicode tables.** They are generated from Python's standard `unicodedata` (Unicode 15.1.0). The generated file records the version.
4. **`tokenizer.json` scope.** Only what SmolLM2 and our trainer use. Everything else is rejected with a named error.
5. **Our trained format.** The same `tokenizer.json` layout, with the same pre-tokenizer and decoder, and `<|endoftext|>` reserved at id 0.
6. **Training algorithm.**
   - Words are counted once. Pair counts are updated incrementally, with a max-heap and lazy invalidation.
   - Ties go to the smallest `(left id, right id)`.
   - Training stops when the best pair occurs fewer than 2 times.
   - `bpe_merges_naive` recounts all pairs at every step and is the oracle.
7. **Integration.**
   - A `Tokenizer` interface and `load_tokenizer` that picks the type from the JSON.
   - `titan tokenizer train --type bpe --vocab N` and `titan tokenizer encode`.
   - `train`, checkpoints, `--resume` and `generate` accept either tokenizer.
   - `generate` stops at `<|endoftext|>` when the tokenizer has one.
8. **Demo.** Train a 4096-token BPE on TinyShakespeare and report the time and bytes per token, for ours and for SmolLM2's. No model training in M4.

Choices this plan makes within those:

- Decoding a special token yields its text (for example `<|endoftext|>`). The stop token is neither returned nor printed.
- Encoding invalid UTF-8 throws and names the byte offset, as the character tokenizer does.
- There is no encode cache. Encoding TinyShakespeare must take less than 10 s in a release build; this is measured, not gated.

**Interfaces:**

- Produces:
  - `bool tokenizer::is_letter(char32_t)` (`\p{L}`: Lu, Ll, Lt, Lm, Lo).
  - `bool tokenizer::is_number(char32_t)` (`\p{N}`: Nd, Nl, No).
  - `bool tokenizer::is_whitespace(char32_t)` (the Unicode `White_Space` property: U+0009–000D, 0020, 0085, 00A0, 1680, 2000–200A, 2028, 2029, 202F, 205F, 3000).
  - `inline constexpr std::string_view tokenizer::kUnicodeVersion`.
  - `std::vector<std::string_view> tokenizer::pretokenize(std::string_view text)`: views into `text`, in order, whose concatenation is `text`. It throws `titan::Error` naming the byte offset for invalid UTF-8.

The script `tools/gen_unicode_tables.py` writes sorted, merged `{first, last}` code-point ranges for L and N, using `unicodedata.category` over U+0000–U+10FFFF. It prints the generated file's path. The header comment of the generated file names the script, the Unicode version and "do not edit". The `White_Space` list is short and stable, so it is hand-written in `unicode_tables.cpp`'s generated section by the script. Lookup is a binary search over the ranges.

`pretokenize` applies two stages.

1. **Digits.** Every `is_number` code point becomes its own piece, and the runs between them become pieces.
2. **GPT-2 split.** Each piece is scanned left to right with the pattern `'s|'t|'re|'ve|'m|'ll|'d| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+`, taking the first alternative that matches at the current position.
   - The contractions are case-sensitive and use ASCII `'`.
   - `\s+(?!\S)` takes a whitespace run minus its last character when a non-space character follows the run. If the run is a single character followed by a non-space, this alternative fails and `\s+` (or `␣?X+`) handles it.

### Task 2: Byte-level BPE encode, decode and `tokenizer.json`

**Files:**

- Create: `src/tokenizer/byte_level.{hpp,cpp}`, `src/tokenizer/bpe_tokenizer.{hpp,cpp}`, `tests/tokenizer/bpe_test.cpp`

**Interfaces:**

- Consumes: `pretokenize` (Task 1).
- Produces:
  - `char32_t tokenizer::byte_to_symbol(std::uint8_t)` and `std::optional<std::uint8_t> tokenizer::symbol_to_byte(char32_t)`.
  - `std::string tokenizer::bytes_to_symbols(std::string_view bytes)`, which returns UTF-8 text in the byte-level alphabet.
  - `class tokenizer::BpeTokenizer` with:
    - `static BpeTokenizer from_json(const io::JsonValue&)`;
    - `io::JsonValue to_json() const`;
    - `std::vector<std::int32_t> encode(std::string_view text) const`;
    - `std::string decode(std::span<const std::int32_t> ids) const`;
    - `std::int64_t vocab_size() const`;
    - `std::optional<std::int32_t> eos_id() const` (the id of the added token `<|endoftext|>`, if present);
    - `std::int64_t num_merges() const`;
    - `static BpeTokenizer from_parts(std::vector<std::string> vocab, std::vector<std::pair<std::int32_t, std::int32_t>> merges, std::vector<std::int32_t> added_ids)`. Here `vocab[id]` is the token's text in the byte-level alphabet, or the literal text for an added token. Task 4 uses it.

The byte-level map is GPT-2's `bytes_to_unicode`. Bytes 33–126, 161–172 and 174–255 map to the same code point. The other 68 bytes, in increasing order, map to U+0100, U+0101, … in turn.

**Encode:**

1. Split `text` on added tokens: at each position, take the longest added-token content that matches. Each match emits its id.
2. Pre-tokenize every remaining span (Task 1), then map each piece with `bytes_to_symbols`.
3. Start from one symbol per byte. While some adjacent pair has a merge rank, take the pair with the lowest rank and merge all of its non-overlapping occurrences left to right. Repeat.
4. Emit the vocabulary id of each final symbol.

**Decode:**

- Concatenate the tokens' texts.
- Map every symbol of a non-added token back to its byte; an added token yields its literal text.
- The result is raw bytes and may be incomplete UTF-8. The id range is checked first.

**`from_json` validation.** Each item has its own test.

- The document is an object, and `model.type` is `"BPE"`.
- These are null or absent: `normalizer`, `post_processor`, `truncation`, `padding`, `model.dropout`, `model.unk_token`, `model.continuing_subword_prefix`, `model.end_of_word_suffix`.
- These are `false`: `model.fuse_unk`, `model.byte_fallback`, `model.ignore_merges`.
- `pre_tokenizer` and `decoder` equal the reference objects above (compared field by field).
- `model.vocab` is an object of string to integer, with ids dense over `[0, n)`, unique, and with 1 ≤ n < 2^31.
- Every non-added vocabulary entry consists only of byte-level symbols, and all 256 single-byte symbols are present.
- Each merge is either `"a b"` (exactly one space) or `["a", "b"]`. `a`, `b` and `a+b` are all vocabulary entries, and no pair appears twice.
- `added_tokens` entries have `special: true`, `normalized: false`, no lstrip, rstrip or single_word, and an `id` equal to `vocab[content]`.

`to_json` writes the layout of decision 5, including `"version": "1.0"` and the reference pre-tokenizer and decoder objects.

- Consumes: `pretokenize`, `bytes_to_symbols`, `BpeTokenizer::from_parts` (Tasks 1 and 2).
- Produces:
  - `struct tokenizer::BpeMerge { std::int32_t left, right; std::int64_t count; }`.
  - `std::vector<BpeMerge> tokenizer::bpe_merges(std::string_view corpus, std::int64_t max_merges)`.
  - `std::vector<BpeMerge> tokenizer::bpe_merges_naive(std::string_view corpus, std::int64_t max_merges)`.
  - `BpeTokenizer tokenizer::train_bpe(std::string_view corpus, std::int64_t vocab_size)`. It requires `vocab_size >= 257` and throws otherwise, naming the value.

**Training:**

- **Ids.** Id 0 is `<|endoftext|>`. Byte `b` is id `1 + b`. Each merge creates the next id, and its text is the concatenation of the two parts' texts.
- **Words.** Remove every occurrence of `<|endoftext|>` from the corpus, splitting at it. Pre-tokenize the rest, and count the distinct pieces as byte strings.
- **Each step.** Pick the pair with the highest count summed over words, weighted by word frequency. Ties go to the smallest `(left, right)`. Stop when the best count is below 2 or `max_merges` is reached.
- **Replacement.** Inside each word, replace the pair's non-overlapping occurrences left to right. This is the same rule as encode.
- **`bpe_merges`.** It keeps pair counts and, per pair, the set of words containing it. It updates both only for the words that changed, and pops a max-heap of `(count, -left, -right)` entries, re-pushing an entry whose count is stale.
- **`bpe_merges_naive`.** It recounts all pairs over all words at every step.
- **`train_bpe`.** It returns a tokenizer with `vocab_size() == 257 + merges.size()`.

### Task 5: Tokenizer interface, stop token and UTF-8 streaming

**Files:**

- Create: `src/tokenizer/tokenizer.{hpp,cpp}`, `tests/tokenizer/tokenizer_test.cpp`
- Modify: `src/tokenizer/char_tokenizer.hpp`, `src/tokenizer/bpe_tokenizer.hpp`, `src/core/utf8.{hpp,cpp}`, `tests/core/utf8_test.cpp`, `src/runtime/checkpoint.{hpp,cpp}`, `src/runtime/generator.{hpp,cpp}`, `src/runtime/sampler.{hpp,cpp}`, `tests/runtime/generator_test.cpp`, `tests/runtime/checkpoint_test.cpp`, `apps/titan/commands.cpp` (compile against the new types only; behaviour is unchanged)

**Interfaces:**

- **`class tokenizer::Tokenizer`.** It has a virtual destructor and these pure virtual `const` methods:
  - `encode(std::string_view) -> std::vector<std::int32_t>`;
  - `decode(std::span<const std::int32_t>) -> std::string`;
  - `vocab_size() -> std::int64_t`;
  - `eos_id() -> std::optional<std::int32_t>`;
  - `to_json() -> io::JsonValue`.

  `CharTokenizer` and `BpeTokenizer` derive from it. `CharTokenizer::eos_id()` returns `std::nullopt`.
- **`std::unique_ptr<tokenizer::Tokenizer> tokenizer::load_tokenizer(const io::JsonValue&)`.**
  - `{"type":"char",…}` gives a `CharTokenizer`.
  - An object whose `model` is an object gives a `BpeTokenizer`.
  - Anything else throws `"unsupported tokenizer document"`, naming what was found.
- **`std::size_t utf8_complete_prefix(std::string_view bytes)`.** It returns the length of `bytes` minus a trailing sequence that is a valid but incomplete UTF-8 prefix of at most 3 bytes. Invalid bytes count as complete.
- **`runtime::checkpoint_tokenizer`.** It returns `std::unique_ptr<tokenizer::Tokenizer>`, using `load_tokenizer`. Its existing checks are unchanged.
- **Stop token.** `Generator::generate` and the `SamplerConfig` overload of `generate_naive` gain a last parameter, `std::optional<std::int32_t> stop_id = {}`. When the sampled token equals `stop_id`, generation ends. That token is neither appended to the result nor passed to `on_token`. The M1 `generate_naive` overload is unchanged.
