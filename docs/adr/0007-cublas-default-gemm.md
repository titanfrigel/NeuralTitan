# Third-party libraries in the build, with cuBLAS as the default GEMM

## Context and problem

ADR 0006 made cuBLAS an optional, off-by-default GEMM backend. It kept the project's own kernels as the default, with a staged path: naive → shared-memory tiling → register tiling. On review, the author asked how much a hand-written GEMM actually teaches about LLMs. The answer:

- **The math teaches nothing new.** `C = A·B` is trivial.
- **The last optimization stages teach GPU tuning, not LLMs.** Register tiling, vectorized loads, bank-conflict avoidance and double buffering take one to two weeks and put the compute budget (NFR-1) at risk.
- **The first two stages do teach something.** A naive kernel and a shared-memory tiled kernel, measured against cuBLAS, teach arithmetic intensity and the roofline model, in about a day. Those concepts explain:
  - why token-by-token decoding is bandwidth-bound;
  - why KV caching, batching and quantization matter;
  - why FlashAttention exists.

This ADR supersedes ADR 0006.

## Decision drivers

- Learning value per unit of effort: keep the roofline insight, drop the tuning work.
- Meeting the NFR-1 training budget without risk.
- The matmul backward math (`dA = dC·Bᵀ`, `dB = Aᵀ·dC`) stays in project code whichever GEMM runs.
- No new download: cuBLAS ships with the installed CUDA Toolkit 12.6.

## Considered options

| Option | Verdict |
|---|---|
| Own kernels, fully optimized and default (ADR 0006's staged path) | Rejected: one to two weeks of GPU tuning with little LLM insight, and a risk to NFR-1. |
| **Own naive and tiled kernels for learning; cuBLAS as the default GEMM** | **Chosen.** |
| cuBLAS only, no own GPU GEMM | Rejected: loses the measured roofline intuition for about one day saved. |
| Also allow cuDNN or CUTLASS | Rejected: they cover attention, norms and more, hiding the parts the project exists to expose. |

## Decision outcome

Chosen: the build links the C++ standard library, the CUDA runtime and **cuBLAS**. cuBLAS is used for GEMM only (matmul and batched matmul):

- **Linking.** cuBLAS is always built in. Only the `ops/cuda` layer links `CUDA::cublas` and includes `<cublas_v2.h>`. The `TITAN_WITH_CUBLAS` build option from ADR 0006 is dropped.
- **Runtime switch.** `--gemm cublas|naive|tiled` selects the GEMM implementation; the default is `cublas`. Every other op always uses the project's own kernels.
- **Own kernels.** The project writes two CUDA GEMM kernels, naive and shared-memory tiled. Both are kept, tested for parity against the CPU reference and against cuBLAS, and benchmarked. There is no register-tiled kernel.
- **Math note.** `docs/math/matmul.md` records:
  - the measured throughput of each kernel next to the GPU's peak compute and bandwidth;
  - the arithmetic-intensity analysis;
  - the backward derivation.
- **Parity.** cuBLAS runs in FP32 without TF32 tensor-core math, so results stay comparable with the CPU reference.

The project still writes its own:
- test harness;
- JSON parser;
- safetensors reader;
- checkpoint format;
- Unicode tables (generated by a script and committed as source);
- every kernel other than the production GEMM.

OpenMP remains excluded; CPU parallelism uses `std::thread`.

## Consequences

- The NFR-1 GPU budget no longer depends on hand-tuned kernels.
- About one week less work in M2.
- cuBLAS is proprietary NVIDIA code under the CUDA Toolkit license, and it becomes a hard dependency of the CUDA build. Its DLL comes from the toolkit and is not committed to the repository.
- cuBLAS stores matrices column-major. The `ops/cuda` wrapper maps our row-major layout by computing `Cᵀ = Bᵀ·Aᵀ`, and the matmul math note documents the mapping.
- Development-only tooling outside the build (ADR 0004) is still governed separately and never linked.
