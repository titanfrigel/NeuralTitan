# Third-party libraries in the build, with optional cuBLAS

## Context and problem

ADR 0003 limits the build to the C++ standard library and the CUDA runtime, so the project's own code exposes every part of an LLM. In a transformer, matrix multiplication accounts for the large majority of compute: the Q/K/V and output projections, the MLP, the LM head, and the attention score and value products. It is also the hardest kernel to make fast by hand. That puts the compute budget for training on TinyStories (NFR-1, about 8 hours) at risk. The author wants cuBLAS available as a fallback, while the project's own kernels remain the primary path. This ADR supersedes ADR 0003.

## Decision drivers

- Learning value: the project's own matmul kernels stay written, tested and readable.
- Budget safety: a known-fast GEMM exists if the own kernels miss NFR-1.
- A trustworthy reference: a vendor GEMM to benchmark and cross-check the own kernels against.
- No new download: cuBLAS ships with the CUDA Toolkit 12.6 already installed (`cublas.lib`, `cublas64_12.dll`).

## Considered options

| Option | Verdict |
|---|---|
| Standard library and CUDA runtime only (ADR 0003 as is) | Rejected: no fallback if the hand-written GEMM misses the compute budget. |
| **Own kernels primary; cuBLAS optional for GEMM, behind a build option and a runtime switch** | **Chosen.** |
| cuBLAS as the default GEMM | Rejected: the own kernels would become dead weight, against the learning goal. |
| Also allow cuDNN / CUTLASS | Rejected: they cover attention, norms and more, hiding the parts the project exists to expose. Softmax, norms and the other non-GEMM ops are bandwidth-bound and simple enough to write. |

## Decision outcome

Chosen: the build links only the C++ standard library and the CUDA runtime. The single exception is **cuBLAS**, used for GEMM only:

- **Build option.** CMake option `TITAN_WITH_CUBLAS`, `OFF` by default. When `ON`, only the `ops/cuda` layer links `CUDA::cublas`.
- **Runtime switch.** A GEMM backend selector (`--gemm own|cublas`, default `own`) picks the implementation for matmul and batched matmul. All other ops always use the project's own kernels.
- **Parity.** cuBLAS runs in FP32 without TF32 tensor-core math, so results stay comparable with the CPU reference and the own kernels.
- **Tests and benchmarks.** When cuBLAS is built in, the parity tests also check the own GEMM against it, and the matmul benchmark reports own versus cuBLAS throughput.

The project still writes its own:
- test harness;
- JSON parser;
- safetensors reader;
- checkpoint format;
- Unicode tables (generated by a script and committed as source);
- every kernel, including GEMM.

OpenMP remains excluded; CPU parallelism uses `std::thread`.

## Consequences

- The M6 compute budget has a fallback that requires no restructuring.
- A second GEMM path to keep in parity; the tests cover it.
- cuBLAS is proprietary NVIDIA code under the CUDA Toolkit license. It is linked only when the option is on, and its DLL is not committed to the repository.
- cuBLAS stores matrices column-major. The `ops/cuda` wrapper handles the row-major mapping (computing `Cᵀ = Bᵀ·Aᵀ`), and the matmul math note documents it.
- Development-only tooling outside the build (ADR 0004) is still governed separately and never linked.
